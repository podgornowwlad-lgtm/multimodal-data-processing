## Окружение (с которым получены результаты)

- Google Colab, Python 3.13.16, PyTorch 2.11.0+cu130, NumPy 2.4.6, Linux 6.6.159 (x86_64, glibc 2.39).
- Среда выполнения: GPU **Tesla T4** (так напечатала ячейка «Воспроизводимость»).
- Код написан на чистом PyTorch и не привязан к устройству. Модель в ноутбуках не переносится
  на GPU (нет `.to('cuda')`), поэтому вычисления идут на процессоре машины Colab, а T4 только
  подключён; результаты от наличия T4 не зависят.
- Нужен Python 3.10+ (в коде `int | None`). Локально: `pip install -r requirements.txt`.
- Версии и устройство печатает ячейка «Воспроизводимость» (сразу после установки torch) в
  каждом ноутбуке.

## Seed

`SEED = 42` задаётся в ячейке «Воспроизводимость» обоих ноутбуков (`random`, `numpy`, `torch`,
`torch.cuda`). Заготовленная ячейка обучения в задании ставила `torch.manual_seed(0)`; она
заменена на `torch.manual_seed(SEED)`. Перед генерацией seed тоже ставится заново, поэтому
текст воспроизводится.

Независимый локальный прогон тех же ноутбуков (Python 3.12.3, PyTorch 2.15.0, CPU) дал те же
значения потерь с точностью до напечатанных знаков и тот же сгенерированный текст. На других
версиях PyTorch последние знаки могут отличаться из-за порядка операций с плавающей точкой.

## Как воспроизвести

1. Откройте `dz1-attention.ipynb` в Colab (или Jupyter) → Run all. Для совпадения со средой
   прогона можно выбрать Runtime → Change runtime type → T4 GPU, но на результат это не влияет.
   Последняя проверка выводит `пройдено 17 из 17` и `Все проверки зелёные.`
2. Откройте `dz1-bughunt.ipynb` → Run all. Проверки 17 из 17; ячейка с экспериментом показывает,
   какие проверки ловят каждый баг; ячейка обучения печатает потери на шагах 0, 100, …, 500 и
   итог (`3.1566 → 0.4431 → 0.0885 → 0.0561 → 0.0454 → 0.0428`, итог `3.157 -> 0.029`).
   Рядом с ноутбуком (в Colab — в `/content`, вкладка Files) сохраняются `loss_curve.png`,
   `generated_sample.txt` и `bug_ablation.png`.
